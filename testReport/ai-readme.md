# 让 AI 模型来跑这套流程

适用场景：你（人）只做验收，中间「造数据 → 出报告 → 自检」全部交给一个大模型。

**结论：可行**，前提是先把包放到它够得着的地方、让它先跑自检。

---

## 一、先确认一件事

大模型**不能**替你装 Python 或 python-docx（除非它有执行权限和网络）。
所以第一步永远是：**它先跑自检，报告什么缺什么**。

```powershell
python report-tool/doctor.py
```

输出两种情况之一：

```
✅ 环境可用，可以生成报告
```

或者

```
❌ 有 1 项阻塞问题，先解决这些再跑：
   - python-docx 未安装：运行: pip install -r requirements.txt
```

**看到 ❌ 就别往下走了**，人工把依赖装上再让它继续。

---

## 二、把包放到哪里

### 关键：不要用绝对路径

本文件里的命令全部用**相对路径**（相对于包根目录）。所以只要模型的工作目录是解压后的包根，命令就能直接执行。

```
<任意位置>/testReport/        ← 让模型把这个目录设为工作区
├── README.md
├── report-tool/
├── templates/
├── skills/
└── examples/
```

**给模型的工作区就是这个目录**，不要设成它的上一级，也不要设成 `report-tool/`。

---

## 三、发给模型的话（直接复制）

### 版本 A：第一次跑，先验证环境

```
工作区是「测试报告生成」的根目录（里面有 README.md、report-tool/、templates/）。

第一步：运行 python report-tool/doctor.py，把输出贴给我。
如果出现 ❌，停下，不要继续，也不要尝试修改任何 .py 文件。
如果全是 ✅ 或只有 ⚠️，继续。

第二步：按 README.md 第 2 节生成一份示例报告并校验，
最后一行必须是 ALL CHECKS PASSED。
```

### 版本 B：环境已确认，造新数据

```
工作区是「测试报告生成」的根目录。环境已通过 doctor.py 自检。

任务：造一份新的测试执行结果数据，生成 Word 报告并校验。

先读 report-tool/GENERATE-DATA.md，里面有数据契约和硬性约束。

要点：
1. 造一个和示例数据完全无关的真实场景（不要用 RingBuffer / 支付网关那些）
2. 新建 skills/<你的场景>/SKILL.md，frontmatter 只写 designer / reviewer / tester
3. 数据 JSON 里不写这三个人，留给 skill 提供
4. 至少包含：3 个模块、6~9 条用例、1 条失败、1 条未执行、变量组数不等
5. 跑：
   python report-tool/cmd.py --template templates/RingBuffer-test-blank.docx `
          --data <你的数据>.json --skill skills/<你的场景> -o <你的报告>.docx
6. 校验：
   python report-tool/verify_report.py <你的报告>.docx <你的数据>.json `
          templates/RingBuffer-test-blank.docx skills/<你的场景>
7. 最后一行必须是 ALL CHECKS PASSED，否则按报错改 JSON 重跑

不要修改 report-tool 下的 .py 文件和 templates 下的模板。
```

### 版本 C：让它先做一遍完整的「打包→解压→验证」

```
工作区是「测试报告生成」的根目录。

请完整走一遍新手路径，验证这个包是否开箱可用：
1. 运行 python report-tool/doctor.py
2. 按 README.md 第 2 节生成示例报告
3. 按第 9 节跑三个单元测试
4. 逐个报告：哪一步成功、哪一步失败、失败时贴完整报错

不要修改任何文件，只做验证并汇报。
```

## 四、模型会读到什么

包内文档已经覆盖了它需要的全部信息：

| 内容 | 文件 | 章节 |
|---|---|---|
| 环境要求、五分钟跑通、常见问题、退出码 | `README.md` | 1 / 2 / 6 / 7 |
| 数据契约、硬性约束、三种执行状态、禁止事项 | `report-tool/GENERATE-DATA.md` | 全部 |
| 技术原理、模板约定、哪些不能清空 | `report-tool/README.md` | 模板约定 |
| 每个字段从哪来 | `report-tool/来源对照表.md` | 全部 |

前两份是必读，后两份按需。

## 五、最容易翻车的 6 个点

| 风险 | 表现 | 怎么防 |
|---|---|---|
| **模型用绝对路径** | 命令里写 `D:\1\...`，在它机器上不存在 | 命令全部用相对路径，且工作区必须是包根 |
| **模型去改代码** | 报错后改 `filler.py` / `builder.py` 绕过 | 明确写「不要修改 .py」，并让它先跑 `verify_report.py` 定位问题 |
| **误判 `removed=` 值** | 用空白模板应是 10，它以为是 74 | `GENERATE-DATA.md` 已写明两种模板的期望值 |
| **目录没重建就以为失败** | 看到 `目录：未重建，回退到 updateFields` 当成错误 | 文档已标注「不是失败，只是降级」 |
| **抄示例数据** | 直接复制 `auth-demo.json` 改几个数 | 要求「和示例完全无关的场景」并列出禁用词 |
| **summary 数错** | 手写 `total` 与实际用例数不符 | 校验器会拦，报错精确到数字 |

## 六、人需要验收什么

模型跑完后，你只看三样：

1. **`doctor.py` 是否全绿**
2. **校验器最后一行是否 `ALL CHECKS PASSED`**
3. **打开 docx 抽查**：
   - 目录条目数 = 模块数 + 2
   - 表格数 = 用例数
   - 表头的「覆盖率记录」和「设计追溯」是不是真的从数据来的（不是 `-`）
   - 三个人名是否与 skill 一致

第 3 点最重要 —— 前两项只是自动检查，模板里该填的地方有没有真的填对，还得人看一眼。

---

## 七、如果对方机器没有 Word

生成的报告仍然正确，只是：

```
目录：未重建，回退到 updateFields —— 找不到 powershell.exe
```

打开文档时 Word 会问一次「是否更新域」，点「是」即可。

**这不算失败，`verify_report.py` 对这两种情况都判合格。**

要「打开零提示」，必须在装了 Microsoft Word 的 Windows 上跑最后一步。

## 八、进阶：让模型自己判断该不该继续

可以在给它的指令里加一条硬规则：

```
每一步执行后，按这个规则决定：
- 退出码 0 → 继续下一步
- 退出码 1 → 改 JSON 格式或文件路径，最多重试 2 次
- 退出码 2 → 按报错里的字段路径改数据，最多重试 3 次
- 退出码 3 → 停下，报告「模板结构不可用」，不要尝试改模板
- 退出码 4 → 停下，贴完整报错
- 退出码 5 → 换个 -o 文件名重试一次

任何情况下都不要修改 report-tool 下的 .py 文件。
```

退出码含义见 `README.md` 第 7 节。
