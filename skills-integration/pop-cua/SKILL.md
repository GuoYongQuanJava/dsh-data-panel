# POP 界面集成测试（CUA 通道）

被测系统**有真实 GUI 测试平台（POP），断言依据是「界面上看到什么 / 控件树读到什么」**时走这套方法。

**REQUIRED BACKGROUND:** 必须已加载主 Skill `ai-integration-test-workflow`。本文件不另起流程——
六步流程、版本模型、用例与步骤的数据契约、报告生成全部由主 Skill 决定。
本文件只补充「被测平台是 POP 这一类 Qt 界面时，**执行步骤**该怎么做、断言读哪里、坑在哪」。

> **与 `zzkz-sim` 的分工（重要，别选错）**
>
> | 你要验的 | 用哪个专项 |
> |---|---|
> | 「点这个按钮，界面/控制台该出现什么」——真实 GUI 链路 | **本文件（pop-cua）** |
> | 「不启 GUI，直接往总线注帧、看下游报文」——headless 路线 | [zzkz-sim](../zzkz-sim/SKILL.md) |
>
> 两条路的被测对象是同一个系统，但**执行通道、断言面、能覆盖的功能完全不同**：
> GUI 路线能验「页面守卫、菜单置灰、弹窗、科目按钮」，headless 路线验不了 UI 状态；
> headless 路线能稳定复现、不受页面 50ms 守卫影响，GUI 路线做不到。
> **同一轮测试里选定一条，不要混着写用例。**

> **换项目时的替换点**：页号表、控件清单、场景门控公式、条件报文表、控制台串**全部作废**。
> 能带走的是：**「先修 UIA 再谈自动化」「读结构不猜截图」「按钮灰亮是机器可读断言」**这三条方法论。

## 红线（破一条，结果不可信）

1. **【必要】先确认 UIA 树可读，再谈自动化。**
   `get_window_state` 读出来的元素数如果只有个位数（5-8 个），说明这个构建**没做过 UIA 修复**
   （见 [uia-fix.md](uia-fix.md)）。此时**不要退回截图猜坐标**——那会产出无法复现的假证据。
   正确做法：明确报告「该构建 UIA 未修复，无法做确定性断言」，并给出修复方法。

2. **【必要】坐标只在自绘面上才允许用，且必须标注。**
   自绘面（平显 HUD、页 119 字段行、108/109 雷达圆弧）不在 UIA 树里，
   用坐标时必须同时写明「此处为自绘面，按源码级基线核对，坐标为估算」。
   标准控件上**一律**用 `AutomationId` / `Name` 定位。

3. **【必要】断言不回写预期值。**
   `observed` 只写 `verify_state` / `get_window_state` / 控制台**真实返回**的文字，
   不写「按钮已点亮」「符合预期」。

4. **【必要】只操作本轮确认的实例。**
   不按 exe 名批量清理进程——同名进程可能属于别人的测试床。
   重启服务前必须确认 PID 是本轮起的。

5. **【必要】区分「能进」和「驻留」。**
   按钮亮（`SensorTestButtonDis`）和场景确认（`SceSelValid`）是**同一条消息里的两个独立字段**。
   「能进、几秒被踢、还能再进」是自洽的，不要写成缺陷。详见 [pitfalls.md](pitfalls.md)。

**菜单排布**（每区域一份 level-1 菜单，两行 ×10）：

- 行 1：机动测试 → 传感器测试 → 自主探测测试 → 自主飞行测试 → 条件测试 → 数据发送 → 周期发送 → 全流程 json → 雷达测试 → 光雷测试
- 行 2：自主攻击（在机动测试正下方）→ 全流程空战 → 操纵杆 → 飞控信息 → ZMQ 汇聚 → 本机信息 → 探测列表 → 导弹告警 → 模型参数 → 仿真信息

**菜单按钮三态**（2bit，`CMenuButton::SetButtonState`）：

| 值 | 外观 | UIA 里 | 能不能点 |
|---|---|---|---|
| 0 | 灰字 | `enabled=false` | ❌ 点了没反应 |
| 1 | 青字 | `enabled=true` | ✅ 可进 |
| 2 | 青字 + 青边框（正在执行） | `enabled=true` | ✅ |

> **灰按钮点了没反应 → 任何场景都要「点亮再点」。**
> 三态可以直接当门控断言：`verify_state` 断言 `enabled` 就行，不用看颜色。
>
> 菜单置灰每 **1s** 刷一次（`CViewMenu::UpdateButtonStates`），MM 每 **25ms** 重算门。

## 操作标准（UIA 修复后）

```
get_window_state（不带截图）→ 按 Name / AutomationId 找控件 → invoke
   → verify_state 断言 enabled / 文字
   → 截图仅作存证（放到 evidence[]，不参与判定）
```

**为什么这么要求**：截图找坐标慢、不准、布局一变就点错；而且坐标点击产出的结论**无法复现**。
UIA 修复后主窗口布局态元素从 8 个涨到 118~142 个，全部菜单按钮暴露
`Name`（=按钮文字）/ `AutomationId`（=objectName）/ `invoke` / `enabled`。

**定位写法**：

- 菜单按钮：`AutomationId` 形如 `CMainWindow.CViewLayout.CViewArea.CViewMenu.CMenuButton.m_btn_menu`
- **多区域会有多份同名钮** → 按 `CViewArea` 顺序选，或用区域下标限定
- 页面内控件：`Name` = 界面中文文字（**含换行的要保留 `\n`**，如「指定\n探测区域」「退出\n自主空战」）

## 通用前置（任何场景进入前都要做）

| 步 | 做什么 | 断言 |
|---|---|---|
| 1.1 | 起四服务（MM/SS/TDM/SAR） | 出现 MM 控制台窗口（~20s）；按键必须 `delivery_mode:"foreground"` + 定向 pid/window |
| 1.2 | 起 POP | 先出 console 窗口，主窗口 ~10s 后才出现；重启时可从 console 断言 `[sendSceneSelect ...] success` |
| 1.3 | **POP 全屏（硬规则）** | `is_on_screen=true`；半屏时设置页空白；**最小化后 UIA 空树、点击被拒** |
| 1.4 | 选多区域布局 | 每区域各一份菜单，可同时开「条件测试」「数据发送」「场景页」 |

> **全屏做法**：点标题栏「最大化」；如果只到半屏，先点「还原」再 `set_window_frame(0,0,1920,1080)`。

**红线 4 条（GUI 操作面）**：

1. **禁点「平显 HUD」** —— 自绘，无 UIA，点不准。
2. **禁按 ESC** —— ESC = 回首页，会把已开页面全拆掉。
3. **布局定下后不要再切** —— 切布局 = 页面重建，DSU 线程随页销毁。
4. **页面开在哪个区域取决于点的是哪份菜单** —— UIA `Invoke` 不会丢点，无需为像素点击规避特定区域。

## 节奏（判断超时用，别乱猜）

| 环节 | 周期 | 含义 |
|---|---|---|
| MM 主循环 | **25ms 一拍** | 顺序：`allButtonEnableMonitor → SceneMonitor → hasEnterSceneMonitor → exitInternal → errorControl → sendDmpExpDisInfo` |
| 菜单刷新 | 1s | 置灰状态更新 |
| SS 镜像 | ~1s 延迟 | 断言窗口 **≥3s** |
| tip30s | 1200 拍 × 25ms = **30s** | 不是「进场景即触发」，是退出条件命中后才起表 |

## 能力边界：这套方法测什么、测不了什么

**能测**：

- 菜单按钮灰/亮（门控公式正确性）
- 场景进入/退出链（握手、审批、弹窗）
- 科目按钮（页 100 十六科目、页 101 三科目）
- 条件注入后的界面反馈（页 104 → 菜单置灰变化）
- 页面内标签值（标准 QLabel 全部 UIA 可读）

**测不了 / 只能间接验**：

| 目标 | 为什么 | 替代做法 |
|---|---|---|
| 平显 HUD 内容 | `QGraphicsView` 自绘，无 UIA 节点 | 源码级基线核对 + 截图存证，结论标 `unconfirmed` |
| 页 119 字段行数值 | 自绘 | 同上，或**转总线探针**（读 DDS 帧） |
| 108/109 雷达圆弧 | 自绘 | 同上 |
| 108/109 页的枚举按钮 | 自绘，且**不发 DDS**（纯显示回填） | 只截图存证，不作断言 |
| 物理 HOTAS 杆量 | 不在自动化能力内 | 用页 104 条件 12「HOTAS 手动退出」代替 |
