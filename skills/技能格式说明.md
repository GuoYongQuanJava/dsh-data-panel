# DSH Skill 格式说明

> 适用：DeepSeek Harness（0.2.2-rc.1）+ `@michengai/dsh-skills-manager`
> 本文所有规则都对照插件源码 `lib/core.js`（`parseSkillDoc` / `entryOf` / `hostAcceptableSkillName`）与本机实测整理，不是凭印象写的。

---

## 一、技能是什么

一个技能 = **一个目录 + 目录里一个 `SKILL.md`**。

```
C:\Users\PC\.dsh\skills\
└── excel-sheet-split\           ← 目录名（可以中文，但建议英文）
    ├── SKILL.md                 ← 必须有，文件名精确匹配
    └── （可选）其它资源文件      ← 脚本、模板、参考资料
```

DSH 启动时扫描这些目录，把每个技能的 **name + 一行 description** 放进 Agent 的常驻清单（很省 token）；当任务匹配时，Agent 再主动读取 `SKILL.md` 正文（按需加载）。

---

## 二、放在哪里（扫描路径与优先级）

| 来源 | 全局目录 | 项目目录 | 可写性 |
|---|---|---|---|
| DSH | `%USERPROFILE%\.dsh\skills` | `<项目>\.dsh\skills` | 可读写 |
| 公共 Agent | `%USERPROFILE%\.agents\skills` | `<项目>\.agents\skills` | 可读写 |
| 外部 Agent（Codex / Claude Code / Cursor / Copilot 等） | 各自目录 | 各自目录 | **只读**（插件只扫描不改） |
| DSH 内置预设（如「创造模式」） | 安装目录 `app.asar` 内 | — | **只读**，无开关 |

规则：

- **项目级同名技能覆盖全局同名技能**；被覆盖的那份会记一笔「遮盖」，界面上标出来源；
- **不扫描** `<项目>\skills`（就是普通的 skills 文件夹，DSH 不认），必须是 `.dsh\skills` / `.agents\skills`；
- 同一个技能不要在多个位置各放一份（会出现"同一名字两份"，容易改错文件）。

---

## 三、文件整体结构

```markdown
---
name: my-skill
description: 一句话说明这个技能何时使用、做什么、产出什么。
---

# 正文标题

正文内容……
```

- `---` 包裹的部分叫 **frontmatter**，写"元数据"；
- 第二个 `---` 之后是 **正文**，写"怎么执行"；
- 两者之间**必须**有第二个 `---`，否则整份文件会被当成没有元数据的正文（技能不可用）。

---

## 四、frontmatter 逐项说明

### 4.0 解析器不是完整 YAML（重要）

DSH 与技能管理器用的是**按行正则解析**，不是标准 YAML 解析器：

```js
/^([A-Za-z0-9_-]+)\s*:\s*(.*)$/
```

由此得出五条硬性结论：

| 规则 | 说明 |
|---|---|
| 键只能用 字母 / 数字 / `_` / `-` | 不能有点号、空格、中文（`metadata.foo:` 解析不到） |
| 冒号前后空格可有可无 | `name:test` 能读，`name: test` 也能读（但**建议写空格**，见下） |
| 只支持"键: 值"一层 | **不支持**嵌套对象、数组、列表形式的字段 |
| 不写 `key: value` 的行会被**静默忽略** | 不会报错，但也不会生效（很容易写出"以为生效了"的字段） |
| 重复的键，**最后一个生效** | 不是报错，而是悄悄覆盖 |

> 为什么仍建议 `name: test`（冒号后加空格）：本插件宽松能读，但标准 YAML 工具（编辑器插件、其他解析器、CI 检查）会把 `name:test` 读成一个普通字符串。写空格是零成本的可移植性。

### 4.1 `---` 边界

| 项 | 规则 |
|---|---|
| 起始标记 | 必须是**文件第 1 行**，且内容只有 `---`（前后有空格无所谓，`trim()` 后等于 `---`） |
| 结束标记 | 往下找到的第一个 trim 为 `---` 的行 |
| 文件开头有 BOM | 插件会剥掉 BOM（`stripBom`），但**建议不要存成带 BOM 的 UTF-8**，个别工具会出错 |
| 缺 frontmatter | 诊断 `diagnostic.frontmatter.missing`，技能不可启用 |

### 4.2 `name` —— 技能标识符（必填）

| 项 | 规则 |
|---|---|
| 是否必填 | **必填**；缺了 → `diagnostic.name.missing`，不可启用 |
| 合法格式 | `^[a-z0-9]+(?:-[a-z0-9]+)*$` —— 只允许**小写字母、数字、单个连字符**，不能以连字符开头/结尾，不能连续两个连字符 |
| 长度 | ≤ 128 字符 |
| 禁用字符 | `\ / : * ? " < > |`、NUL、`:`（路径非法字符） |
| 首尾 | 不能以 `.` 开头，不能以 `.` 或空格结尾 |
| 中文 | ❌ 不允许（非 ASCII 直接判非法，不会尝试转换） |
| 自动纠正 | 插件会尝试转换：`Split_Excel Tool` → `split-excel-tool`；但**不要依赖它**，直接写规范值 |
| 与目录名关系 | 目录名可以中文（`测试/`），`SKILL.md` 里写英文 name 即可（插件文档称之为"中文目录自救"） |

合法 / 非法对照：

| 写法 | 结果 | 说明 |
|---|---|---|
| `my-skill` | ✅ | 标准写法 |
| `test` | ✅ | 单词也合法 |
| `skill2` | ✅ | 数字可以 |
| `My-Skill` | ⚠️ | 会被转成 `my-skill`，但建议自己写小写 |
| `my_skill` | ⚠️ | 会被转成 `my-skill` |
| `my--skill` | ❌ | 连续连字符，转换后仍非法 |
| `-my-skill` | ❌ | 以连字符开头 |
| `我的技能` | ❌ | 中文，无法转换 |
| `my skill` | ⚠️ | 空格会转成 `-`，建议自己写 |

### 4.3 `description` —— 何时使用（必填）

| 项 | 规则 |
|---|---|
| 是否必填 | **必填**；缺了 → `diagnostic.description.missing`，不可启用 |
| 长度 | 没有硬限制，但**建议 20–80 字 / 一行**——它会常驻在 Agent 的清单里 |
| 内容 | 写"**何时用 + 做什么 + 产出什么**" |
| 标点 | 中文标点没问题，`：` 全角冒号也可以（因为在值里） |
| 引号 | 值里有 `: ` 或 `#` 时，用双引号包起来更安全 |

好的写法：

```yaml
description: 用户要求按列拆分 Excel 时使用：读取源文件，按分店列生成多个 xlsx，不修改原文件。
description: 用户要求把 Excel 报表拆成多个 Sheet 时使用；输出新文件，不改原文件。
```

不好的写法：

```yaml
description: 测试                      # 信息量为零，模型永远不会自动选中
description: 处理文件                  # 太泛，和几十个技能都重叠
description: 这是一个非常强大的技能，可以帮助你完成各种复杂的任务……   # 空话，占位置没用
```

### 4.4 `disable-model-invocation` / `user-invocable`（可选）

控制"谁能调用这个技能"。

| 字段 | 含义 |
|---|---|
| `disable-model-invocation: true` | **禁止模型自动调用**，只有用户点名才生效（适合会改文件、跑构建的技能） |
| `user-invocable: false` | **禁止用户手动点名**，只能由模型自动使用（适合内部子流程） |

合法值（大小写不敏感）：

```
true / yes / on / 1     →  true
false / no / off / 0    →  false
```

其它任何值（`禁用`、`否`、`1.0`、空值 `-`、拼错）→ 诊断 `diagnostic.invocation.invalid`，**并且整条策略被忽略，退回"谁都能调用"**。

两个都不写 = 默认 = 模型可自动调 + 用户可点名。

### 4.5 自定义字段（可选）

解析器不限制键名（只要符合 `[A-Za-z0-9_-]+`），所以可以放业务字段。**它们不影响 DSH 加载技能**，只对认识这些字段的工具/脚本有意义。

```yaml
team: 平台组        # 归属团队
category: 报表      # 分类，便于筛选
```

两点注意：

1. DSH 本身只读 `name` / `description` / 两个调用开关，其它字段写不写都不会报错；
2. 不要把"每次执行都会变的数据"（执行范围、执行结论、覆盖率之类）写死在技能里，否则会和实际执行结果矛盾——那类数据应由执行方产出。

### 4.6 多行值怎么写

支持标准块标量的两种风格：

```yaml
# 折行（>）：多行合并成一行，用空格连接
description: >
  用户要求按列拆分 Excel 时使用。
  读取执行结果 JSON，填入模板，输出 docx。

# 保留换行（|）：换行原样保留
description: |
  按列拆分 Excel 的流程。
  产出：多个 xlsx + 一份汇总行数表。
```

注意：块内容**必须缩进**（至少一个空格），否则会被当成新的键或正文。

### 4.7 frontmatter 里不能这样写

| 写法 | 后果 |
|---|---|
| 嵌套：`meta:` 下一行缩进 `owner: xx` | ❌ 解析器不支持嵌套，`owner` 会被静默忽略 |
| 数组：`tags: [a, b]` 或 `- a` | ❌ 会被当成普通字符串，不是数组 |
| 点号键：`meta.owner: xx` | ❌ 键不匹配正则，整行被忽略 |
| `#` 注释行 | ⚠️ 不解析、不报错；但容易被误认为"注释掉了一个字段"，实际什么都没发生 |
| 同一键写两次 | ⚠️ 后写的覆盖前面的，不报错 |
| 空值：`team:` | ⚠️ 视为空字符串（`team:` 与 `team: ` 都是空） |
| 中文键名：`团队: 平台组` | ❌ 键不匹配正则，被忽略 → 请用英文键名 |

## 五、正文写什么

正文是**技能被加载时喂给 Agent 的操作手册**。frontmatter 负责"何时用"，正文负责"怎么用"。

### 5.1 建议包含的七类内容

| # | 内容 | 例子 |
|---|---|---|
| 1 | 适用边界 | "仅在用户要求拆分 Excel 时使用；只读表格、做统计时不走本技能" |
| 2 | 前置检查 | "先确认源 xlsx 存在、`openpyxl` 可导入；缺了就停下来告诉用户" |
| 3 | 步骤 | "① 读表头 ② 按分店分组 ③ 写 out\ ④ 核对行数 ⑤ 输出汇总" |
| 4 | 可直接复制的命令 | `python split.py --src 导入.xlsx --key 分店 --out out` |
| 5 | 判断规则 / 字段来源 | "哪些数据来自本文件、哪些来自执行结果，写清楚不要互相覆盖" |
| 6 | 输出约定 | "产出 `out\*.xlsx` 与 `out\汇总.txt`，行数合计必须等于源文件" |
| 7 | 失败处理 / 回滚 | "行数对不上就停止，删掉本次生成的 out\ 并原样报错" |

### 5.2 不建议写的

| 内容 | 原因 |
|---|---|
| 大段背景介绍、公司历史、项目沿革 | 加载即占上下文，对执行无帮助 |
| "你是一位资深专家……"这类人设 | 对行为没有约束力 |
| 把 `README.md` 整段抄进来 | 改成"见 `xxx/README.md` 第 N 节"，需要时再去读 |
| 与本技能无关的通用命令 | 容易被误用 |
| 模糊要求（"认真仔细""尽量优化"） | 不可执行，等于没写 |
| 密钥、token、内网密码 | 技能文件会进 Git / 被打包分发 |

### 5.3 路径怎么算

技能正文里出现的**相对路径，以技能所在目录为基准**（DSH 在加载时会给出 base directory，例如 `C:\Users\PC\.dsh\skills\excel-sheet-split`）。

所以要引用项目里的文件，建议写**明确的一层相对路径或绝对路径**，别写"当前目录"这种含糊说法：

```markdown
- 脚本：`D:\tools\split.py`
- 模板：`D:\tools\template.xlsx`（若放在技能目录内，可写 `.\assets\template.xlsx`，加载时以技能目录为基准）
```

### 5.4 长度与成本

| 项 | 建议 |
|---|---|
| 总长度 | 20–60 行最舒服；超过 200 行考虑拆分或把细节放进同目录的其它文件，正文只留"入口 + 关键步骤" |
| 为什么 | 正文只在被加载时读，但**一旦加载就占上下文**；写得越长，那一轮能读的文件越少 |
| 图片/二进制 | 不要放进技能目录除非确实需要（会拖慢扫描） |

## 六、诊断代码与排错

技能管理器会给出 5 类诊断（`entryOf`），命中即计入「诊断异常」，且 `loadable: false` 的技能**开关点不动**：

| 诊断代码 | 触发条件 | 修法 |
|---|---|---|
| `diagnostic.frontmatter.missing` | 第 1 行不是 `---`，或找不到结束的 `---` | 补 frontmatter |
| `diagnostic.name.missing` | frontmatter 里没有 `name`（或为空） | 加 `name: xxx` |
| `diagnostic.name.invalid` | name 不符合 kebab 规则 / 超长 / 含禁用字符 | 改成 `my-skill-name` |
| `diagnostic.description.missing` | 没有 `description`（或为空） | 补一句用途 |
| `diagnostic.invocation.invalid` | `disable-model-invocation` / `user-invocable` 值非法 | 只写 `true` / `false` |

另外两类会计入统计但不算错误：

- **同名被遮盖**（`shadowedBy`）：多个来源有同名技能，优先级低的被盖住；
- **项目根不可用**（`warning.project.missing` / `unreadable`）：工作区目录被删或没权限。

## 七、完整示例（可直接抄）

### 7.1 最小可用

```markdown
---
name: test
description: 演示技能：用户要求验证技能链路时使用，输出工作区路径和一行 test OK。
---

# Test

## 何时使用
用户明确要求"测试技能"或"验证技能是否生效"时。

## 步骤
1. 打印当前工作区路径；
2. 输出一行 `test OK`；
3. 不写任何文件。
```

### 7.2 带执行开关

```markdown
---
name: excel-sheet-split
description: 用户要求按列拆分 Excel 时使用：读取源文件，按分店列生成多个 xlsx，不修改原文件。
disable-model-invocation: true
user-invocable: true
---

# Excel 按列拆分

## 何时使用
- 用户要求把一张大表按某列（如「分店」）拆成多个文件时；
- 不适用：只做统计、透视、合并时。

## 前置检查
- 源文件存在且是 .xlsx；
- `python` 与 `openpyxl` 可用。

## 步骤
1. 读取表头，确认拆分列（默认「分店」）；
2. 按拆分列分组；
3. 写入 `out\`，每个取值一个文件，文件名 = 取值；
4. 核对：各文件行数合计 = 源文件数据行数；
5. 输出 `out\汇总.txt`（每个文件名 + 行数）。

## 命令
```powershell
python split.py --src 导入.xlsx --key 分店 --out out
```

## 输出
- `out\*.xlsx`
- `out\汇总.txt`

## 失败处理
- 行数对不上：停止，删除本次生成的 `out\` 内容，原样报错；
- 源文件被占用（Excel 打开中）：提示用户关闭后重试。
```

### 7.3 反例（常见的坏写法）

```markdown
---
name:test
description:测试
123
---
```

| 问题 | 后果 |
|---|---|
| `name:test` 冒号后没空格 | 本插件宽松能读；但标准 YAML 工具会读成字符串 → 建议加空格 |
| `description:测试` | 能读，但模型无法判断何时用 → 只能手动点名 |
| `123` | 不是字段，**变成正文**；技能加载后只有 "123"，没有步骤 |
| 正文缺失 | 技能没有可执行内容 |

## 八、上线前检查清单

- [ ] 目录里文件叫 `SKILL.md`（大小写精确）
- [ ] 第 1 行是 `---`，且有第二个 `---` 收尾
- [ ] `name` 全小写、连字符分隔、≤128 字符、无中文
- [ ] `description` 写清"何时用 + 做什么 + 产出什么"
- [ ] 布尔字段只写 `true/false`（或 `yes/no/on/off/1/0`）
- [ ] 自定义字段只用 `字母数字_-`
- [ ] 正文有"步骤 + 命令 + 输出"，没有密钥
- [ ] 同一个技能只放在一个位置（全局或项目，别两边都放）
- [ ] 放进目录后刷新技能中心，确认「诊断异常 0」且开关可切换

## 九、附：一条命令自检（PowerShell，只读）

```powershell
$root = 'C:\Users\PC\.dsh\skills'
Get-ChildItem $root -Directory | ForEach-Object {
    $doc = Join-Path $_.FullName 'SKILL.md'
    if (-not (Test-Path $doc)) { "缺少 SKILL.md: $($_.Name)"; return }
    $lines = [IO.File]::ReadAllLines($doc, [Text.Encoding]::UTF8)
    $hasFm = $lines.Length -gt 0 -and $lines[0].Trim() -eq '---'
    $end = -1; for ($i = 1; $i -lt $lines.Length; $i++) { if ($lines[$i].Trim() -eq '---') { $end = $i; break } }
    $map = @{}
    if ($hasFm -and $end -gt 0) {
        for ($i = 1; $i -lt $end; $i++) {
            if ($lines[$i] -match '^([A-Za-z0-9_-]+)\s*:\s*(.*)$') { $map[$matches[1]] = $matches[2].Trim() }
        }
    }
    $name = $map['name']; $desc = $map['description']
    $okName = $name -match '^[a-z0-9]+(-[a-z0-9]+)*$' -and $name.Length -le 128
    "{0,-28} frontmatter={1} name={2}({3}) description={4}" -f `
        $_.Name, $hasFm, $(if ($name) { $name } else { '空' }), $(if ($okName) { '合法' } else { '非法' }), $(if ($desc) { '有' } else { '空' })
}
```
